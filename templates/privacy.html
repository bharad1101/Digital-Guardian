Transparency

Privacy & security

This notice explains what Digital Guardian does with the content you submit.

What is sent to the server

  • The text, URL or QR payload you paste is sent to the backend so it can be analysed.
  • Images and screenshots you upload are analysed in memory and are not stored.
  • Your analysis result (risk score, indicators, recommendations) is stored in your personal history only if you keep history saving enabled.

What is not done

  • Your clipboard is never monitored or read in the background.
  • Links are never opened automatically.
  • Other apps, private messages or notifications are never read or intercepted.
  • Uploaded images are not retained, resold or used to train models.
  • Secrets, passwords and API keys are kept out of the source code.

Security controls

  • Passwords are hashed with a salted one-way algorithm.
  • Cookie-authenticated forms are protected against CSRF.
  • Expensive analysis endpoints are rate limited.
  • Uploads are restricted by type and size; user URLs are treated as untrusted.
  • Security headers (CSP, frame protection, MIME sniffing protection) are applied.
  • One user can never access another user’s history.

Limitations of the analysis

Results are advisory. A low score does not guarantee that content is safe, and a high score does not prove malicious intent. The spam classifier is a general SMS model and may be inaccurate for other languages or message types. Remote URL inspection and real-time threat intelligence are only used when explicitly configured with a real provider — the app never claims intelligence it does not have.
